七、浮层压在站点自己的内容上

站点正文第一段：黑字白底，密排到足以给浮层当"底下滚过去的内容"。樱花与星夜， 粉白与粉紫，一层皮盖在别人的结构上——这一格的存在是为了让"透"这件事可测量， 而不是只能靠肉眼在截图上觉得"好像有点透出底下的字"。下面这几行刻意排得密， 笔画之间的白缝会跟着一起透上来，那才是浮层玻璃化真正的风险：底噪变高、字变糊。

站点正文第二段：同样的密排文字再来一行，保证菜单压住的那块里有字、也有白缝。 浮层在左边偏右一点的位置，正好盖住这一段的中部；如果皮肤只扳透背景而没接管墨色， 菜单里那几行站点自己写的白字就会在半透的面上糊成一团——所以这一格同时判两件事： 透过玻璃看到的纸够不够干净，以及落在纸上的字归不归我们。

八、浅色浮层压在深色块上

/* 站点自己的深色代码块：密集、高对比，专门给上面那层浅色浮层当底 */
function blend(front, back, a) {            // 前景按 α 压在背景上
  var r = front.r * a + back.r * (1 - a);   // 这就是浏览器给玻璃做的事
  var g = front.g * a + back.g * (1 - a);   // 逐通道、线性、不看颜色名
  var b = front.b * a + back.b * (1 - a);
  return { r: r, g: g, b: b, a: 1 };
}
function veil(px, tint, pct) {              // 我们的叠色膜：同一套算式
  return blend(tint, px, pct);
}
站点自己写的浅色浮层：底下是密排的等宽字，笔画缝会跟着一起透上来。 这一格的每一行文字都挂在被后代点名的元素上，好让"后代那条规则"有东西可管。 白天档这一格该透出深色底噪，夜晚档这一格几乎透不出东西。

九、站点用什么名字宣告自己是浮层

站点正文：这一块的密度和上面两格一样，是给五块浮层当"底下滚过去的内容"的取证对象。 樱花与星夜压在别人的结构上，玻璃化之后能不能读，只有把面压在字上才量得出来—— 所以这里排满，笔画缝、行距、标点都要跟着透上来。 第二行同样密排，保证五块面板底下都有字可透，而不是某一块恰好压在空白上。 第三行再来一遍：面板是五块，底噪只能有一块，多出来的那些面板必须共用这一段。 第四行、第五行：这一段故意写得比面板高，这样面板上沿压到的和下沿压到的都是字。 第六行：如果族把不该接管的东西也扳了，这一段的像素会跟着变——那是另一项在管的事。 第七行：这一格里没有卡片也没有表格，底就是密排文字，上面压着七块东西——读数只归因到它们。
